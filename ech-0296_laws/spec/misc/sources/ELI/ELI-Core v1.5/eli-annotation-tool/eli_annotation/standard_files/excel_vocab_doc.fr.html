Décrire un vocabulaire SKOS dans un fichier Excel

Les vocabulaires utilisés par l'outil d'annotation ELI doivent être fournis dans le format SKOS. Un vocabulaire correspond à une entité skos:ConceptScheme et contient plusieurs skos:Concept décrivant chacun un des termes utilisés dans le vocabulaire.

Il est possible de décrire un vocabulaire avec une feuille Excel. Un classeur Excel peut contenir plusieurs feuilles, chacune décrivant un vaocabulaire différent. Les feuilles doivent se conformer à un format spécifique décrit ci-après.

Structure générale de la feuille

La partie supérieure de la feuille est appelée l'entête et contient les métadonnées décrivant le Concept Scheme, c'est-à-dire le vocabulaire lui-même. La partie inférieure est appelée le corps et contient les Concepts, c'est-à-dire les termes présents dans le vocabulaire.

L'entête se termine et le corps commence à la ligne dont la première colonne contient l'expression Concept URI.

Les cellules ne doivent contenir que des données textuelles. Les autres types de données, comme par exemple les hyperliens, peuvent provoquer des erreurs et être ignorés.

Propriétés décrivant les entités

Les entités Concept Scheme et Concept sont décrites grâce à diverses propriétés. Ces propriétés peuvent être :

  • des propriétés DCTERMS dont le nom est préfixé par dct:
  • des propriétés SKOS dont le nom est préfixé par skos:
  • n'importe quelle autre propriété dont le préfixe a été déclaré dans l'entête

Par exemple :

dct:title
skos:prefLabel
euvoc:status

Dans l'exemple précédent, le préfixe euvoc dont être déclaré et associé à l'espace de nommage http://publications.europa.eu/ontology/euvoc#.

Lorsqu'une valeur de propriété peut être dans différentes langues, il est possible de déclarer le nom de la propriété et la langue des valeurs. La langue est spécifiée par son code en deux lettres. Dans de tels cas, il est possible de déclarer plusieurs fois une même propriété avec des langues différentes à chaque fois. Par exemple :

skos:altLabel@en
skos:altLabel@fr

Certaines propriétés peuvent avoir de multiples valeurs. Dans ce cas, il est possible de déclarer le nom de la propriété avec le caractère qui va servir à séparer les différentes valeurs. Par exemple :

skos:altLabel@en[separator=","]
skos:narrower[separator=";"]

Entête

L'entête décrit le Concept Scheme, c'est-à-dire le vocabulaire lui-même. Les propriétés sont définies dans un ensemble de lignes consécutives. La première colonne contient le nom de la propriété et la deuxième colonne la valeur de cette propriété. Par conséquent, l'entête est un tableau avec deux colonnes et autant de lignes que nécessaire.

La première ligne de l'entête définit l'URI du Concept Scheme. Le nom dans cette première colonne doit être ConceptScheme URI et la deuxième colonne doit contenir l'URI du skos:ConceptScheme.

Les lignes suivantes contiennent les propriétés décrivant le Concept Scheme. Ces propriétés sont soit des propriétés SKOS ou DCTERMS valides, soit d'autres propriétés préfixées par un préfixe personnalisé.

Les préfixes personnalisés utilisés dans l'entête ou dans le corps doivent tous être déclarés dans l'entête, chacun sur une ligne dans la première colonne sera le préfixe lui-même, préfixé par prefix: et dont la seconde colonne sera l'URI associé à ce préfixe.

Les propriétés invalides et les propriétés dont le préfixe n'a pas été déclaré sont ignorées lors du traitement du fichier.

Voici un exemple d'entête :

ConceptScheme URIhttp://data.sparna.fr/vocabularies/days
dct:title@enWeekdays
dct:description@enThe days of the week
dct:description@frLes jours de la semaine
euvoc:statushttp://publications.europa.eu/resource/authority/concept-status/CURRENT
prefix:euvochttp://publications.europa.eu/ontology/euvoc#

Corps

Le corps décrit les Concepts présents dans le Concept Scheme, c'est-à-dire les termes du vocabulaire. Chaque ligne définit un Concept différent, les colonnes correspondant aux diverses propriétés décrivant ce Concept. Par conséquent, le corps est un tableau avec autant de colonnes qu'il y a de propriétés et autant de lignes qu'il y a de Concepts.

La première ligne du corps contient les noms des propriétés utilisées pour décrire les Concepts. Comme explique plus haut, la première colonne de cette ligne doit contenir l'expression Concept URI. Les colonnes suivantes sont soit des propriétés SKOS ou DCTERMS valides soit d'autres propriétés préfixées par un préfixe personnalisé. Les préfixes personnalisés doivent avoir été déclarés dans l'entête.

Les propriétés invalides et les propriétés dont le préfixe n'a pas été déclaré sont ignorées lors du traitement du fichier.
